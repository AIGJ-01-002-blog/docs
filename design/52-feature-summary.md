# 팀 블로그 플랫폼 기능 총정리

> 정리 기준: 2026-10-07. 저장소에 실제 존재하는 01~45 번호 문서 30개를 모두 읽고, 51 통합 ERD와 대조했다.
> 이 문서는 요구사항·설계의 기능 목록이다. 서비스 구현 완료 여부를 뜻하지 않는다. 원문 문서는 수정하지 않았다.

## 1. 범위와 문서 판단 기준

세 팀원이 같은 회원·글·권한·데이터 규칙을 공유하고, 개인 서비스의 화면과 확장을 달리 만드는 블로그 플랫폼이다. 공통은 1인 1블로그이며, 블로그 주소는 `/@handle`, 글 주소는 `/@handle/posts/{id}`다.

| 구분 | 문서에 정의된 범위 | 해석 |
| --- | --- | --- |
| Tier A | 로그인·프로필·블로그·글 작성·자동 저장·발행·공개 범위·삭제·홈·상세·내 글 관리·소유 권한 | 공통 필수 기준 |
| Tier B | 태그·사진·댓글/답글·좋아요·조회수 | 01의 권장 범위이며, 후속 문서와 통합 ERD에 모두 포함 |
| Tier C | 검색·알림·팔로우 피드·트렌딩·AI 태그 추천·신고/숨김·탈퇴 화면·다크 모드 | 후속 문서에 구체적 설계가 있음. 01의 1차/2차 우선순위 문장은 남아 있으므로, 설계가 있다는 이유만으로 모두 1차 필수라고 단정하지 않음 |
| 최근 추가 공통 | 친구 요청·수락, 친구의 최근 활동 표시, 본인의 마지막 로그인 표시, 동의 버전·재동의 | 2026-10-07 결정 기록 기준 |
| 선택 규격 | 친구 공개 `FRIENDS`, 친구 알림 | 기본 비활성. 친구 맺기 자체는 공통 |
| 개인 확장 | 그룹·미션·카테고리·시리즈·북마크·발행 이력 등 | 공통 기능을 유지하면서 추가하는 기능 |

오래된 문장과 새 결정이 다르면 [01 결정 기록](./01-common-requirements.md)의 2026-10-07 결정을 우선했다. DB 구조는 [03의 기준 안내](./03-erd.md), [51 통합 ERD](./51-erd-unified.md), [V1 DDL](../erd/V1__common_schema.sql)을 따른다. 현재 통합 ERD는 **20개 테이블·148개 컬럼**이며, 초기 17개·139개 기준에서 변경됐다.

최신 공통 화면은 **React + REST API**, 로그인은 **Redis 세션 쿠키 + CSRF**다. 이전 문서의 SSR/JWT 자유 선택 및 JS 미사용 시 SSR 대체 문장은 현행 공통 기준으로 사용하지 않는다. 화면 색·글꼴·배치·썸네일 비율은 개인 선택이며, 표시 정보·페이지 크기·상태·문구는 공통이다.

## 2. 회원·계정 기능

### 2.1 가입·로그인·로그아웃

- 이메일/비밀번호, Google, GitHub로 가입·로그인한다. 네이버는 공통 범위에서 제외한다.
- 같은 로그인 수단의 같은 사용자로 계정을 중복 생성하지 않는다. 같은 이메일이라도 로그인 수단이 다르면 별도 계정이며 자동 병합·계정 연결은 없다.
- 소셜 첫 가입 때 닉네임·블로그 주소·필수 약관을 확인하는 가입 마무리 화면을 둔다.
- 세션은 마지막 활동을 기준으로 14일 유지한다. 로그아웃하면 세션 및 브라우저의 본인 임시 데이터를 정리한다.
- 로그인 5회 연속 실패 시 15분 잠금 등 계정·IP별 요청 제한을 둔다.
- 로그인 실패와 비밀번호 찾기는 가입 여부를 알 수 없는 공통 안내를 사용한다. 가입 화면의 중복 이메일·탈퇴 유예 계정 안내는 유지하기로 결정했다.
- 본인 계정 화면에 마지막 로그인 일자와 로그인 방식을 표시한다.

출처: [01](./01-common-requirements.md), [07](./07-auth.md), [44](./44-withdraw.md), [51](./51-erd-unified.md).

### 2.2 이메일 인증·비밀번호 관리

- 이메일 가입자는 인증 링크로 이메일을 확인한다. 인증 링크는 24시간 유효하며 한 번만 사용한다.
- 인증 메일 재발송을 제공하고, 새 링크 발급 시 이전 링크를 무효화한다. 기본 제한은 1분 1회·하루 10회다.
- 이메일 인증 전에도 로그인할 수 있지만 글 작성·발행·댓글·사진 업로드·좋아요·신고는 막는다.
- 비밀번호는 8~16자이며 영문·숫자·특수문자를 각각 포함한다. BCrypt로 해시 저장한다.
- 비밀번호 찾기/재설정 메일을 제공한다. 재설정 링크는 30분 유효·일회용이며, 재설정 후 모든 기기에서 로그아웃한다.
- 이메일 가입자는 현재 비밀번호를 확인한 뒤 변경할 수 있다. 변경 후 다른 기기를 로그아웃시키고 알림 메일을 보낸다.

출처: [07](./07-auth.md), [11](./11-profile.md), [42](./42-permission-matrix.md).

### 2.3 프로필·계정 설정·동의

- 본인의 닉네임·소개·프로필 사진을 수정한다. 프로필은 한 번에 저장하며 항목 하나라도 실패하면 전부 취소한다.
- 소개는 글자만 0~200자·최대 4줄이며 이모지를 허용한다. HTML·Markdown·주소 자동 링크는 제공하지 않는다.
- 프로필 사진은 브라우저에서 정사각형으로 자른 256×256 WebP를 사용한다. 없으면 닉네임 첫 글자 기본 아이콘을 표시한다.
- 소셜 가입 때 사용자가 소셜 사진을 우리 저장소에 복사할 수 있다. 복사에 실패해도 가입은 완료하고 기본 사진을 사용한다.
- 이메일과 가입 후 블로그 주소는 변경하지 않는다.
- 새 글의 기본 공개 범위를 PUBLIC/PRIVATE 중 선택한다.
- 필수 이용약관·개인정보 처리방침과 선택 AI 동의를 종류·버전·동의 일자로 기록한다.
- 현재 문구 버전과 다르면 로그인 때 재동의를 받는다. AI 동의는 설정에서 철회할 수 있다.
- 친구에게 최근 활동을 보여 줄지 설정한다. 숨기면 본인도 다른 친구의 최근 활동을 볼 수 없다.

출처: [01](./01-common-requirements.md), [07](./07-auth.md), [11](./11-profile.md), [34](./34-ai-tag-suggest.md), [51](./51-erd-unified.md).

### 2.4 블로그 주소·닉네임

- 블로그 주소는 가입 때 자동 제안하고 한 번 직접 수정할 수 있다. 가입 이후에는 변경하지 않는다.
- 주소는 소문자·숫자·밑줄 기반이다. Google/GitHub 가입은 각각 `go-`/`gi-` 접두어를 사용한다. 중복·예약어·금칙어를 검사한다.
- 대문자로 들어온 주소는 소문자 주소로 이동한다. 탈퇴 후에도 주소를 재사용하지 않는다.
- 닉네임은 2~10자 완성형 한글·영문·숫자이며 글자를 하나 이상 포함한다. 공백·자음/모음만·숫자만인 이름은 허용하지 않는다.
- 대소문자를 무시해 중복 검사하며, 정규화·금칙어 변형·예약어 검사를 한다.
- 닉네임을 바꾸면 30일 동안 다시 바꾸지 못한다. 이전 닉네임은 즉시 다른 사람이 쓸 수 있다.
- 글과 댓글에는 현재 닉네임과 변경되지 않는 `@handle`을 함께 표시한다.

출처: [08](./08-blog-address.md), [09](./09-nickname.md), [13](./13-delete-withdraw.md).

## 3. 글 작성·저장·발행 기능

### 3.1 에디터·미리보기·안전한 본문

- 제목과 Markdown 본문을 작성한다. 제목은 발행 시 1~100자, 본문은 1~100,000자가 필요하다.
- CommonMark와 GFM의 제목·목록·인용·강조·취소선·링크·표·체크리스트·코드 블록 등을 지원한다.
- 서버 미리보기 API를 통해 발행 화면과 같은 렌더링 결과를 보여 준다. 코드 강조를 지원한다.
- 직접 입력한 HTML은 글자로 표시하고, 서버의 허용 목록 정화와 CSP로 스크립트 실행을 막는다.
- 외부 링크는 안전한 새 탭 링크로 표시한다. 외부 사진 및 남이 올린 사진 주소는 본문 사진 연결 대신 링크로 처리한다.
- 본문 사진은 본인이 올린 저장소 사진만 연결한다. 저장소 주소가 바뀌면 옛 주소를 인식해 현재 주소로 렌더링한다.
- Markdown 원문과 정화된 HTML을 따로 보관한다. 렌더링 규칙 변경 시 기존 글을 다시 렌더링할 수 있다.
- 각주·수식·Mermaid·임베드·목차 화면·코드 복사 버튼은 개인 확장이다.

출처: [01](./01-common-requirements.md), [05](./05-publish.md), [12](./12-content-sanitize.md), [23](./23-image.md).

### 3.2 임시글·자동 저장·오프라인 복구

- 새 글을 시작하면 임시글을 만들며, 내 글 관리에서 다시 열어 이어 쓴다.
- 자동 저장 대상은 제목과 본문이다. 태그는 발행할 때 확정한다.
- 브라우저 IndexedDB → 서버 Redis → PostgreSQL의 3단계로 저장한다. 기본은 브라우저 1초, 서버 전송 입력 중단 3초/최대 30초, DB 반영 1분이다.
- 수동 저장과 발행은 DB에 즉시 반영한다. 저장 중·저장됨·로컬 저장·오프라인·충돌 상태를 표시한다.
- 오프라인에서도 본문을 쓰고 사진을 대기열에 넣을 수 있다. 연결이 돌아오면 재시도하고 동기화한다.
- 미반영 내용이 있으면 페이지 이탈 때 안내한다. 로그아웃하면 본인의 브라우저 임시 데이터와 사진 대기열을 지운다.
- 비어 있고 방치된 임시글은 24시간 기준으로 정리한다. 사람이 빈 임시글을 삭제하면 바로 완전 삭제한다.

출처: [04](./04-draft-and-image.md), [05](./05-publish.md), [13](./13-delete-withdraw.md).

### 3.3 여러 탭·기기 충돌과 발행본/작업본 분리

- 편집 버전으로 오래된 저장이 새 내용을 덮어쓰지 못하게 한다.
- 충돌하면 서버 내용과 본인 내용을 비교하고 차이를 강조한다.
- 사용자는 확인 후 덮어쓰기, 서버 내용 불러오기, 별도 임시글로 분리, 로컬 편집 계속 중에서 선택한다. 서버 내용을 불러올 때 기존 로컬 내용은 백업한다.
- 발행 글 수정 중에는 별도 작업본을 저장한다. 독자는 마지막 발행본을 계속 읽는다.
- 수정 취소는 작업본을 지우고 발행본을 유지한다. 발행 이력 전체를 보관하거나 과거 버전으로 되돌리기는 개인 확장이다.

출처: [03](./03-erd.md), [04](./04-draft-and-image.md), [05](./05-publish.md), [51](./51-erd-unified.md).

### 3.4 발행·재발행·공개 범위

- 발행 전에 제목·본문·사진 업로드 완료·태그·공개 범위를 검증한다. 업로드 대기 사진이 남으면 발행을 막는다.
- 발행 버튼 연타·중복 요청으로 같은 발행이 반복되지 않게 한다.
- 재발행해도 글 주소·최초 발행 일자·최초 공개 일자·좋아요/댓글/조회 수를 유지한다. 재발행 일자를 별도로 기록해 수정됨을 표시한다.
- 공통 공개 범위는 PUBLIC/PRIVATE다. 처음 전체 공개된 일자가 공개 목록 정렬 기준이며, 공개를 껐다 켜도 다시 바뀌지 않는다.
- 공개 범위는 재발행 없이 즉시 변경한다. 수정 작업본과 반응 기록은 유지한다.
- 발행 글을 다시 임시글 상태로 돌리는 기능은 없으며 비공개로 전환한다.
- 남의 임시글·비공개·휴지통·숨긴 글은 없는 글과 동일하게 404로 처리한다. 작성자의 예외는 본인 상세 및 관리 화면에만 적용한다.
- 친구 공개는 별도 선택 구현이다. 현재 공통 V1의 공개 범위 CHECK에는 PUBLIC/PRIVATE만 있다.

출처: [01](./01-common-requirements.md), [05](./05-publish.md), [06](./06-visibility.md), [43](./43-report-hide.md), [51](./51-erd-unified.md).

## 4. 읽기·탐색·관리 기능

### 4.1 홈 최신 글·개인 블로그

- 홈은 공개·발행·미삭제·미숨김·탈퇴하지 않은 작성자의 글을 처음 공개된 일자 최신순으로 보여 준다.
- 글 카드는 썸네일·제목·200자 요약·날짜·작성자·좋아요 수·댓글 수를 포함한다. 조회수는 카드에 넣지 않는다.
- 9개씩 커서 기반 더 보기로 이어 붙인다. 뒤로 가면 목록과 스크롤을 최대 30분 기준으로 복원한다.
- 개인 블로그 상단은 프로필·소개·공개 글 수를, 아래는 그 사람의 공개 글 목록을 보여 준다. 본인도 블로그 공개 페이지에서는 비공개 글을 보지 않는다.
- 로딩·빈 목록·오류/재시도·사진 없음·404 상태를 마련한다. 반응형·키보드 접근을 지원한다.
- 날짜는 24시간 이내 상대 시각, 이후 날짜로 표시한다. 카드의 열 수·색·사진 비율은 개인 선택이다.

출처: [01](./01-common-requirements.md), [10](./10-post-list.md), [11](./11-profile.md).

### 4.2 글 상세·공유 미리보기

- 제목·작성자/프로필·발행/수정 일자·본문·태그·좋아요·조회수·댓글·작성자 소개·팔로우·신고를 보여 준다.
- 작성자는 편집·공개 범위 변경·삭제를 할 수 있고, 수정 중 작업본 이어 쓰기와 취소를 제공한다.
- 본인 글 좋아요·신고·본인 팔로우 버튼은 표시하지 않는다. 비회원/미인증 회원에게는 좋아요·신고 버튼을 보여 주고 로그인/인증을 안내한다.
- 알림에서 이동한 특정 댓글을 찾아 강조하며, 접힌 답글을 열어 보여 준다. GIF 재생 제어와 사진 지연 로딩을 지원한다.
- 잘못된 작성자 주소는 읽을 수 있는 글에 한해 정식 주소로 이동한다. 작성자의 임시글 상세는 에디터로 이동한다.
- 공유용 제목·요약·대표 사진·canonical·Open Graph 메타를 제공한다. 서버가 링크 미리보기 메타와 실제 404 응답을 처리한다.
- 공개가 아닌 글은 검색 엔진과 공개 sitemap에서 제외하고 개인 화면 캐시를 제한한다.

출처: [01](./01-common-requirements.md), [06](./06-visibility.md), [21](./21-comment.md), [40](./40-post-detail.md), [42](./42-permission-matrix.md).

### 4.3 내 글 관리·휴지통

- 내 글 관리에 임시글·발행 글·휴지통 탭을 둔다. 본인 글만 20개씩 더 보기로 표시한다.
- 임시/발행 목록은 최근 수정순, 휴지통은 최근 삭제순이다. 발행 목록에서 공개/비공개 필터와 수정 중·관리자 숨김 상태를 확인한다.
- 새 글 작성·임시글 이어 쓰기·발행 글 보기/편집·작업본 취소·공개 범위 변경·삭제를 제공한다.
- 삭제하면 즉시 공개 화면에서 사라지고 휴지통에서 30일 보관한다. 복구하면 원래 상태·목록 위치·반응 기록을 유지한다.
- 휴지통에는 남은 보관 일수를 표시하고, 사용자가 완전 삭제할 수 있다. 완전 삭제는 확인 후 실행한다.
- 30일 뒤 자동 완전 삭제하며 해당 글의 다른 사람 댓글도 함께 삭제한다.
- 관리 화면 검색·일괄 처리·작성자 통계 화면은 개인 확장이다.

출처: [13](./13-delete-withdraw.md), [41](./41-manage-posts.md), [42](./42-permission-matrix.md).

### 4.4 태그·태그 탐색

- 글에 기본 최대 10개 태그를 붙이고 제거·순서 변경한다. 최대 개수는 설정값이다.
- 태그는 소문자·Unicode 정규화·공백 하이픈 변환 후 중복을 제거한다. 1~30자이며 `C++`, `C#`, `node.js`, `.net` 같은 기술명을 지원한다.
- 로그인 사용자는 태그 접두어 자동완성을 사용한다. 본인 사용 태그와 공개 글 태그를 활용하고 남의 비공개 태그는 노출하지 않는다.
- 태그별 공개 글 목록, 전체 태그 상위 100개, 블로그 안 태그 필터를 제공한다.
- 단일 `#태그` 검색은 태그 페이지로 이동한다. 태그를 고쳐 재발행하면 수정됨을 표시한다.

출처: [01](./01-common-requirements.md), [22](./22-tag.md), [33](./33-search.md).

### 4.5 검색

- 전체 공개 글 검색과 사람 검색을 탭으로 제공하며, 특정 블로그 안 글 검색도 지원한다.
- 글 검색 대상은 제목·태그·Markdown 본문이다. 사람은 닉네임·블로그 주소로 검색한다.
- 검색어는 최대 50자·5개 단어이며 단어는 AND 조건이다. 한 글자 단어는 제외하고, 두 글자는 제목/태그, 세 글자 이상은 본문까지 검색한다.
- 관련도순/최신순을 제공한다. 관련도는 제목 일치 → 제목/태그 일치 → 본문 포함 순위를 기본으로 한다.
- 일치 문구를 안전하게 강조한다. 글은 9개, 사람은 20개씩 더 보기를 제공한다.
- 비공개·임시·휴지통·숨김·탈퇴 작성자의 글은 제외한다. 검색어 원문은 로그에 남기지 않는다.
- 기간/주제 조건·의미/하이브리드 검색·검색어 자동완성·인기 검색어는 개인 확장이다.

출처: [06](./06-visibility.md), [22](./22-tag.md), [33](./33-search.md).

### 4.6 트렌딩

- 홈에 최신/트렌딩 탭을 제공한다. 최근 7일 안에 처음 공개된 글을 대상으로 한다.
- 좋아요·작성자 외 서로 다른 댓글 작성자·조회수에 가중치를 주고 글 나이가 늘수록 점수를 낮춘다.
- 기본 점수는 `(3 × 좋아요 + 2 × 댓글 작성자 + 0.1 × 조회) / (경과 시간(h) + 2)^1.5`다.
- 좋아요 또는 작성자 외 댓글 작성자 반응이 하나 이상 있어야 하며, 한 작성자의 글은 최대 3개다.
- 10분마다 상위 100개 스냅샷을 만들고 더 보기 중에는 동일 스냅샷 순위를 유지한다. 만료되면 다시 불러오기를 안내한다.
- 조회 시 현재 공개 권한을 다시 확인한다. Redis 장애 때는 DB로 첫 페이지를 계산한다.
- 오늘/주/월 탭·사이드바 인기 글 5개·첫 글/새 작가·주제/태그별 트렌딩은 개인 확장이다.

출처: [30](./30-like.md), [31](./31-view-count.md), [32](./32-trending.md), [43](./43-report-hide.md).

## 5. 사진·반응·관계·알림 기능

### 5.1 사진 업로드·관리

- jpg/png/gif/webp, 원본 10MB 이하를 지원한다. 서버가 파일 확장자뿐 아니라 실제 내용·크기·치수를 검증한다.
- 브라우저에서 사진 축소·WebP 변환·EXIF 제거와 640px 썸네일을 생성한다. 일반 사진의 기본 최대 폭은 1920px다.
- Presigned URL로 MinIO에 직접 업로드하고, 완료 API가 확인한 사진만 글/프로필에 사용한다.
- 본문 삽입·삭제·대체 텍스트 입력·첫 사진 썸네일 생성을 지원한다. 대체 텍스트는 권장 사항이며 발행을 막지는 않는다.
- GIF는 제한 내에서 애니메이션을 유지하고 첫 프레임 썸네일 및 재생 제어를 제공한다. APNG/애니메이션 WebP는 첫 프레임만 사용한다.
- 사진은 오프라인 대기열·재시도·취소를 지원한다. 본문은 계속 저장할 수 있지만 대기 사진이 있으면 발행할 수 없다.
- 기본 용량은 회원당 1GB(원본+썸네일 등), 하루 업로드 발급 200회이며 사용량과 한도 안내를 제공한다.
- 임시 업로드는 24시간, 연결 해제 사진은 7일 후 정리한다. 현재 사용 중인 프로필 사진은 보호한다.
- 탈퇴 30일 익명 처리 후의 사진은 다음 정리 배치에서 삭제한다. 비공개 글 사진도 주소를 알면 볼 수 있다는 기존 결정을 유지한다.

출처: [01](./01-common-requirements.md), [04](./04-draft-and-image.md), [11](./11-profile.md), [23](./23-image.md).

### 5.2 댓글·답글

- 이메일 인증을 마친 회원이 1~1,000자 글자 댓글/답글을 작성한다. HTML/Markdown/주소 자동 링크는 지원하지 않는다.
- 공통 답글 깊이는 1단계다. 답글에 답하면 같은 단계에 두고 대상 회원을 표시한다.
- 오래된 댓글부터 최상위 20개씩 표시한다. 답글은 처음 3개를 보여 주고 더 보기로 펼친다.
- 현재 닉네임·블로그 주소·작성자 배지·작성/수정 일자를 표시한다. 알림으로 특정 댓글에 이동할 수 있다.
- 본인의 댓글만 수정·삭제한다. 글 주인도 남의 댓글을 삭제할 수 없고 신고를 이용한다.
- 답글이 있는 댓글 삭제 시 삭제 문구로 자리를 남겨 대화를 보존한다. 답글이 없는 댓글은 행을 삭제한다. 댓글 복구 기능은 없다.
- 관리자 숨김 댓글은 타인에게 안내 문구, 본인에게 원문과 숨김 안내를 보여 준다. 답글은 유지하며 숨김 댓글 편집·새 답글은 막는다.
- 중복 내용·요청 횟수를 제한하고, 화면 댓글 수는 삭제·숨김 댓글을 제외해 집계한다.

출처: [21](./21-comment.md), [42](./42-permission-matrix.md), [43](./43-report-hide.md).

### 5.3 좋아요·조회수

- 이메일 인증 회원은 남의 읽을 수 있는 글에 좋아요를 등록/취소한다. 자기 글에는 누르지 못한다.
- 회원당 글당 1건을 보장하고 중복 요청에도 원하는 상태를 유지한다. 화면에 즉시 반영하되 실패하면 복구한다.
- 좋아요 수를 함께 갱신하고 정기적으로 원본 행과 맞춘다. 비공개 전환·휴지통·수정 중에도 반응 기록을 보존한다.
- 조회수는 글이 보이는 탭에서 1초 지난 뒤 기록한다. 작성자 본인·봇·링크 미리보기·미리 불러오기·볼 수 없는 글은 제외한다.
- 기본 중복 기준은 같은 방문자/같은 글 24시간 1회이며 개인 설정으로 바꿀 수 있다.
- 로그인 회원 번호/익명 방문자 쿠키로 구분하고, 쿠키가 없으면 날마다 바뀌는 IP+User-Agent 해시를 쓴다. 원래 IP는 저장하지 않는다.
- Redis에 모은 조회수를 1분마다 누적/일별 통계에 반영한다. 일별 조회수는 90일 보관하고 누적 조회수는 유지한다.
- 조회수는 상세에만 표시한다. 기록 실패는 읽기를 막지 않으며, 이 집계는 장애 때 완전한 정확성을 보장하는 통계가 아니다.
- 좋아요한 사람/내가 좋아요한 글 목록·댓글 좋아요·작성자 통계 화면은 개인 확장이다.

출처: [30](./30-like.md), [31](./31-view-count.md), [40](./40-post-detail.md), [42](./42-permission-matrix.md).

### 5.4 팔로우·친구·최근 활동

- 팔로우는 승인 없는 단방향 관계다. 로그인 회원이 등록/취소하고 자기 팔로우는 금지한다.
- 공개 팔로워/팔로잉 수·최근순 목록을 제공한다. 로그인 사용자는 팔로우한 사람의 공개 글 피드를 9개씩 본다.
- 탈퇴 유예 회원은 수·목록·피드에서 제외하고 복구 시 다시 표시한다. 30일 뒤 관계를 정리한다.
- 친구는 상호 관계이며 요청·수락·거절·요청 취소·친구 해제를 제공한다. 양쪽이 서로 요청한 경우 친구 수락으로 처리한다.
- 친구 목록은 본인용이다. 수락된 친구에게 최근 활동을 오늘/어제/N일 전/1주 이상으로 표시한다.
- 최근 활동은 요청 시 대략 한 시간에 한 번 갱신한다. 공개 설정을 끄면 본인도 다른 친구의 최근 활동을 보지 못한다.
- 팔로우와 친구는 별개다. 친구 맺기는 공통이지만 친구 공개·친구 요청/수락 알림은 선택이다.

출처: [01](./01-common-requirements.md), [06](./06-visibility.md), [24](./24-follow-feed.md), [51](./51-erd-unified.md).

### 5.5 인앱 알림

- 댓글·답글·좋아요·새 팔로워·팔로우한 사람의 첫 공개 글·신고 처리 결과·내 콘텐츠 숨김의 7종 알림을 제공한다.
- 본인 행동은 알리지 않는다. 댓글/답글 수신자가 겹치면 중복을 줄이고, 탈퇴·읽기 권한·알림 끄기를 확인한다.
- 읽지 않은 좋아요와 팔로우를 묶어 마지막 행동자와 인원 수를 표시한다. 같은 사람의 재행동과 반복 팔로우로 도배되지 않게 한다.
- 첫 전체 공개 때 새 글을 알리고 재발행·재공개로 다시 알리지 않는다.
- 헤더 종의 안 읽은 수(최대 99+), 최근 10개 드롭다운, 전체 목록 20개씩 더 보기, 개별/전체 읽기·개별 삭제를 제공한다.
- 기본 30초 확인을 사용하되 백그라운드 화면에서는 중지한다. 알림을 누르면 해당 글/댓글 등으로 이동한다.
- 접근할 수 없게 된 콘텐츠는 제목/링크를 숨긴다. 신고자·관리자의 신원은 운영 알림으로 노출하지 않는다.
- 일반 5종은 설정에서 끌 수 있고 기존 알림은 유지한다. 신고 결과·콘텐츠 숨김 알림은 끌 수 없다.
- 최근 갱신 기준 90일, 회원당 최대 1,000개를 보관한다. 알림 실패가 원래 글쓰기/반응 처리를 실패시키지 않는다.

출처: [20](./20-domain-events.md), [24](./24-follow-feed.md), [25](./25-notification.md), [43](./43-report-hide.md).

## 6. AI·운영·탈퇴·화면 설정

### 6.1 AI 태그 추천

- 작성자 본인이 이메일 인증·AI 동의를 마친 상태에서 버튼을 눌렀을 때만 실행한다.
- 제목과 현재 본문의 정리된 일부를 이용해 최대 5개 태그를 제안한다. 사용자가 고른 것만 현재 태그에 추가한다.
- 이미 선택한 태그·중복·금칙어·잘못된 응답을 걸러 내고 글당 남은 태그 자리만큼 제공한다.
- 새 추천, 로딩·빈 결과·재시도·실패 안내를 제공한다. 본문이 너무 짧으면 호출하지 않는다.
- 설계된 공급자 순서는 Gemini와 자체 Ollama 전환이다. 한도/429와 시간 초과/서버 오류의 전환 시점은 34의 규칙을 따른다.
- 같은 내용/비슷한 수정의 결과를 Redis 캐시로 재사용한다. 기본 사용자당 하루 실제 호출 20회이며 캐시 재사용은 차감하지 않는다.
- 외부 전송 내용과 공급자 데이터 사용 안내를 받고 동의하며 설정에서 철회할 수 있다. 회원 이메일·닉네임·다른 글은 요청에 넣지 않는다.
- 실패해도 저장·발행은 계속 가능하다. 제목/요약/주제/관련 글/티저 추천은 개인 확장이다.
- 비공개·친구 공개 글을 Ollama로만 처리하자는 34 F-1은 아직 미결이다. 확정된 공통 기능으로 적지 않는다.

### 6.2 신고·관리자 숨김·회원 정지

- 인증 회원이 남의 읽을 수 있는 글/댓글을 신고한다. 자기 콘텐츠·회원 프로필 신고는 공통 범위에서 허용하지 않는다.
- 사유는 스팸/광고·욕설/혐오·성적 콘텐츠·개인정보·저작권·기타다. 기타는 200자 이내 설명이 필수다.
- 중복 신고 및 기본 회원별 분당 5회·하루 50회 요청을 제한한다.
- 최신 구조는 대상별 신고 사건과 회원별 신고를 분리한다. 대상당 대기 중 사건은 하나이며 처리 뒤 새 신고는 새 사건이 된다.
- 관리자는 대기/처리 목록, 신고 수·사유·최초 신고 시점 콘텐츠 스냅샷·처리 이력을 확인한다.
- 신고 수만으로 자동 숨기지 않는다. 관리자가 검토해 숨김 또는 기각하고 신고자에게 결과, 작성자에게 숨김을 알린다.
- 글 숨김은 공개 목록/검색/피드/태그/트렌딩/sitemap과 타인의 상세에서 제외한다. 작성자는 본인 원문·숨김 안내를 보고 수정할 수 있지만 재발행으로 숨김을 해제하지 못한다.
- 댓글 숨김은 자리를 남기고 답글은 보존한다. 관리자가 해제하면 댓글 수와 글의 원래 목록 위치를 복원한다.
- 관리자는 1일·7일·30일·영구 정지와 수동 해제를 한다. 정지 사유·기간·관리자·해제 이력을 보관하고 모든 세션을 즉시 종료한다.
- 정지 계정은 로그인하지 못한다. 기간 만료 후 로그인 때 자동 해제할 수 있다. 회원 정지만으로 기존 글을 자동 숨기지는 않는다.
- 관리자는 남의 글을 편집/삭제하거나 비공개 글을 열람하는 권한을 얻지 않는다. 신고 검토에는 신고 시점 스냅샷을 사용한다.
- 자기 신고 사건 처리·자기 콘텐츠 숨김·관리자 계정 정지는 제한한다. 이의 제기·관리자 신규 신고 알림은 개인 확장이다.

출처: [01](./01-common-requirements.md), [42](./42-permission-matrix.md), [43](./43-report-hide.md), [51](./51-erd-unified.md).

### 6.3 회원 탈퇴·복구·익명 처리

- 설정에서 탈퇴 영향·글/댓글/좋아요 등 수량·30일 기한·주소 재사용 불가를 확인하고 탈퇴한다.
- 이메일 가입자는 비밀번호를, 소셜 가입자는 확인 문구를 입력한다. 관리자는 권한을 내려놓기 전 탈퇴할 수 없다.
- 즉시 모든 기기를 로그아웃시키고 본인 글/블로그를 공개 화면에서 감춘다. 탈퇴 완료 및 복구 기한을 메일로 알린다.
- 30일 안에 로그인하면 복구 전용 화면을 보여 준다. **로그인만으로 자동 복구하지 않으며 복구 버튼을 눌러야 한다.**
- 복구하면 기존 글·반응·관계를 다시 살리고 복구 메일을 보낸다. 탈퇴 유예 중에는 복구 등 허용된 절차 외 서비스 이용을 제한한다.
- 30일 후 글·로그인 수단·좋아요·팔로우/친구 관계·알림 등 개인 데이터를 단계적으로 정리하고 회원을 익명 처리한다.
- 답글이 달린 댓글은 내용과 신원을 지우고 탈퇴 안내 자리만 남긴다. 다른 댓글은 삭제한다.
- 블로그 주소는 영구 보존·재사용 금지, 닉네임은 익명 처리 후 해제한다. 최근 활동은 비운다.
- 동의·정지 이력은 최신 회의 결정에 따라 증빙용으로 유지한다. 모든 행이 물리 삭제된다고 설명하지 않는다.
- 탈퇴 30일 익명 처리 후 사진은 다음 정리 배치에서 삭제한다. 탈퇴 전 글 내보내기는 개인 확장이다.

### 6.4 다크 모드·공통 화면 상태

- 시스템/라이트/다크를 헤더에서 전환한다. 기본값은 시스템이며 OS 테마 변경을 따라간다.
- 브라우저에 저장해 페이지 이동·새로고침 뒤 유지한다. 비회원도 사용할 수 있고 기기별로 독립적이며 로그아웃으로 지우지 않는다.
- 첫 화면의 테마 깜빡임을 줄이고 코드 강조 테마를 함께 변경한다. 글 사진 자체는 색을 바꾸지 않는다.
- 명도 대비·키보드·버튼 이름·색 외 상태 구분·동작 줄이기 설정을 고려한다.
- 로딩/빈 목록/오류/재시도/404, 저장 상태, 로그인·이메일 인증 안내는 공통이다. 색·폰트·배치 스타일은 개인 서비스가 정한다.
- 계정별 테마 저장과 기기 간 동기화는 개인 확장이다.

운영·품질 요구사항도 기능 범위에 포함한다.

- 하나의 Spring Boot 배포 단위에서 기능별 모듈을 나누며, 다른 모듈 변경은 공개 Service/이벤트로 요청한다. MSA는 공통 범위에서 사용하지 않는다.
- PostgreSQL·Flyway·Redis·MinIO를 사용한다. DB 변경은 마이그레이션으로 관리하고 실제 PostgreSQL 검증을 지향한다.
- 요청 제한·중복 방지·원자적 카운터·편집 버전·발행 멱등성·페이지 커서로 중복/충돌을 처리한다.
- 공통 이벤트는 커밋 후 비동기이며 알림 유실을 허용한다. 카운터·탈퇴 데이터 정리·정지 세션 종료 등 필수 처리를 유실 가능한 알림 이벤트에 맡기지 않는다.
- 알림·AI·조회 기록 실패가 주된 글 저장/발행/읽기를 막지 않도록 한다. 자동 저장 장애는 저장 상태 및 브라우저 데이터로 사용자에게 드러낸다.
- Redis 장애 때 세션은 비로그인으로 처리해 공개 읽기를 유지한다. 요청 제한/중복 방지는 통과시키고 인증·재설정 토큰은 거부하며 AI는 503으로 처리한다.
- XSS 정화·CSP·CSRF·보안 쿠키·실제 파일 검증·신뢰 프록시 IP 판별·비밀값 외부 주입으로 보안을 지킨다.
- 목록/상세의 N+1을 피하고 필요한 정보만 조회한다. 성능 수치는 설계 목표/프로토타입 결과이며 실제 배포 성능 보증이 아니다.
- 공통 API 오류 형식, 마이크로초 시각의 불투명 Base64URL 커서, 잘못된 커서 400, `/api/...` 복수형 및 `/api/me/...`, OpenAPI 명세를 따른다.
- 시작 템플릿은 Spring Boot+React, 공통 V1, PostgreSQL/Redis/MinIO Compose, 보안·오류·CI를 포함한다.
- 채택된 CI/CD 방향은 PR 검사·dev 테스트·main 배포·자동 롤백과 알림/리뷰 연동이다. Maven·커버리지 40% 기준이 있으며 NHN 배포 형태·SonarQube 등 확인 항목은 남아 있다.

## 10. 선택 기능과 개인 확장

### 10.1 선택 공통 규격

- **친구 공개 `FRIENDS`:** 상호 수락된 친구에게만 글을 공개한다. 현재 DB CHECK를 확장하고 친구 공개 목록 인덱스를 추가하는 별도 마이그레이션이 필요하다.
- **친구 요청/수락 알림:** 현재 공통 7종 알림과 별도로 선택 도입한다.
- **post 수직 분할:** 글 뼈대·본문·통계 분리는 별도 제안 파일이다. 이미 3정규형인 post의 수직 분할이며 필수 기능이나 적용된 스키마로 설명하지 않는다.

출처: [01](./01-common-requirements.md), [06](./06-visibility.md), [25](./25-notification.md), [51](./51-erd-unified.md), [수직 분할 제안](../erd/OPTION-post-split.sql).

### 10.2 팀원별 개인 확장

공통으로 빠진 확장도 있다: 좋아요한 사람/내가 좋아요한 글 목록, 특정 작성자의 새 글 알림만 끄기, 관리 화면 검색/일괄 처리, 회원 프로필 신고, 이의 제기, 관리자 신고 알림, 탈퇴 전 글 내보내기, 테마 기기 간 동기화, 설정 화면의 모든 기기 로그아웃 버튼, 각주·수식·Mermaid·임베드 등이다. 이들에 임의로 담당자를 배정하지 않았다.

01의 개인 확장 표에는 휴지통 및 `post_view_daily`가 김민서 확장처럼 남아 있으나, 후속 13·31·41 및 통합 ERD에서는 공통이다. 발행본/작업본 분리와 충돌 감지도 공통으로 올라왔으므로 개인 전용 기능으로 세지 않았다.
