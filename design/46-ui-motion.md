# 화면 움직임 설계

작성 2026-10-12 · 기능 명세 `specs/095-ui-motion` · 이슈 devlog#176 (목표 #169)

민서님 요청: "우리 ui에 에니메이션이나 이펙트가 없는거 같은데 한번 추가해서 사용자가 우리 블로그를 이용하면서 부드러운 사용감을 줄 수 있도록 설계해서 gif로 보여줘".

## 1. 원칙

| 원칙 | 이유 |
|---|---|
| 새 라이브러리 없이 CSS 전환·애니메이션 | 첫 화면 JS를 늘리지 않는다. 강사님이 지적한 성능·과한 구성을 피한다 |
| `transform`·`opacity`만 움직인다 | 브라우저가 레이아웃을 다시 계산하지 않고 합성만 해서 휴대폰에서도 끊기지 않는다 |
| 짧게, 조금만 | 사용자를 기다리게 하지 않는다. 움직이는 거리는 4~10px |
| 나타날 때만 움직이고 닫을 때는 바로 | 닫힘을 기다리게 하지 않는다. 닫힘 애니메이션은 컴포넌트를 남겨 두는 코드를 늘린다 |
| 첫 화면은 움직이지 않는다 | 서버가 그린 첫 화면을 React가 다시 그릴 때 깜빡이거나 LCP가 늦어지지 않게 |
| 동작 줄이기를 켜면 모두 끈다 | 어지럼을 느끼는 사용자 배려(WCAG 2.3.3) |

## 2. 움직임 토큰 (`styles.css` `:root`)

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--motion-fast` | 120ms | 버튼 누름, 메뉴 펼침 |
| `--motion-base` | 200ms | 모달, 알림 띠, 탭·칩 색 바뀜, 배지 |
| `--motion-slow` | 320ms | 목록 등장 |
| `--ease-out` | `cubic-bezier(0.2, 0.7, 0.2, 1)` | 기본 곡선. 빨리 시작해 부드럽게 멈춘다 |
| `--ease-spring` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | 살짝 튀는 곡선. 좋아요 하트, 배지 |

## 3. 효과

| 자리 | 움직임 | 시간 |
|---|---|---|
| 화면 이동 | 본문 자리가 흐림에서 또렷하게(opacity만). transform은 안의 position: fixed를 흔들어서 쓰지 않는다 | 180ms |
| 글 목록(카드, 첫 화면 브랜치 목록) | 아래에서 10px 올라오며 나타남. 앞 6줄은 40ms씩 엇갈림. 브랜치 목록은 줄기 그림은 두고 글 내용만 | 320ms |
| 모달 | 막은 흐려지며, 상자는 8px 아래에서 0.97배 → 제자리 | 200ms |
| 내 메뉴·알림·언어 목록 | 오른쪽 위(단추 쪽)에서 6px·0.98배 → 제자리 | 120ms |
| 알림 띠 | 위에서 8px 내려옴 | 200ms |
| 알림 개수 배지 | 0배에서 튀어나옴 | 200ms |
| 버튼·칩·고르기·아래 탭 | 누르는 동안 0.96~0.97배(아래 탭 아이콘 0.88배) | 120ms |
| 최신·트렌딩 탭, 브랜치 칩 | 고른 칸 바탕·글자색이 부드럽게 바뀜 | 200ms |
| 좋아요 | 막 누른 순간에만 하트가 1.35배로 한 번 튐 | 420ms |

이미 있던 것: 툴팁(055), 목차의 부드러운 스크롤, 댓글 강조, 내 글 관리 뼈대 깜빡임.

## 4. 첫 화면을 움직이지 않는 방법

`lib/motion.ts`의 `armMotion()`이 사용자의 첫 스크롤·클릭·키 입력을 기다렸다가 `<html>`에 `motion-ready`를 붙인다. 목록·배지 등장 효과는 `.motion-ready` 아래에서만 걸린다. 그래서 처음 열었을 때는 서버가 그린 화면과 똑같이 그려지고, 그 뒤 탭을 바꾸거나 다른 화면에서 목록을 받거나 무한 스크롤로 더 받을 때부터 움직인다. 화면 이동 흐림도 첫 경로에서는 하지 않는다.

## 5. 고르고 뺀 것

| 후보 | 결정 | 이유 |
|---|---|---|
| 카드에 마우스를 올리면 뜨기 | 빼기(그대로) | 068에서 산만하고 휴대폰에서 뜬 채로 남아 뺐다 |
| 닫힘 애니메이션 | 빼기 | 코드가 늘고 기다림이 생긴다 |
| View Transitions API·Framer Motion | 빼기 | 지원이 고르지 않거나 라이브러리 무게가 는다 |
| 사진이 다 받아지면 서서히 보이기 | 빼기 | 사진마다 JS 처리가 필요하다 |
