# devlog 확장 설계 (spec 088~091, V32~V33)

작성 2026-10-11, 고침 2026-10-13 · 매일 저장소·다국어 점검. [64 devlog 확장 설계](./64-devlog-extensions-077-083.md)(spec 077~087)에 이어, 그 뒤 devlog에서 공통 설계(테이블·API·구조·권한)를 바꾼 기능만 모았습니다. 화면 움직임(spec 095)은 [46 화면 움직임 설계](./46-ui-motion.md)에 따로 있습니다. 기능의 세부 규칙과 화면은 코드 저장소의 기능 명세 `specs/NNN-*`이 기준입니다.

근거: [devlog CHANGELOG](https://github.com/AIGJ-01-002-blog/devlog/blob/develop/CHANGELOG.md) v1.65.0~v1.66.2와 develop의 `[Unreleased]`, 마이그레이션 V32~V33. 2026-10-12부터 목표 단위 Git Flow라 V33은 develop에만 있고 다음 릴리스(v1.67.0)에 main으로 들어갑니다.

## 2. ERD에 더해진 컬럼·규칙 (V32~V33)

| 테이블·컬럼 | 마이그레이션 | 핵심 |
|---|---|---|
| `post.ai_diary` | V32 | boolean, 기본 false. 자정 AI 일기가 만들 때 정하고 바꾸지 않음. 기존 일기는 제목 `YYYY-MM-DD 개발 일기`로 찾아 true |
| `friendship` | V33 | 이미 탈퇴 신청(`member.status = 'WITHDRAWN'`)한 회원의 남은 친구 관계를 한 번 지움. 이후에는 탈퇴 신청 처리에서 바로 지움 |

## 3. 개발·릴리스 구조

2026-10-12부터 목표 단위 Git Flow입니다(devlog `CONTRIBUTING.md`). 기능은 `develop`에서 딴 `feature/*`에서 만들어 `develop`으로 합치고 버전을 올리지 않습니다. 목표(마일스톤) 이슈가 모두 닫히면 `develop`을 `main`에 합치며 다음 마이너 버전으로 릴리스하고, 운영 배포는 main에서 백엔드·화면 테스트가 통과한 뒤에만 합니다. 급한 장애·보안만 `hotfix/*`로 패치 릴리스합니다.
