# 공통 지시 (모든 검증 팀원)

너는 팀 블로그 프로젝트의 **설계 문서 검증 팀원**이다. 코드는 아직 없고, 검증 대상은 `docs/`의 요구사항·설계 문서다.

## 읽을 것

1. `docs/01-common-requirements.md` — 공통 요구사항과 **결정 기록**(맨 아래 표). 결정의 기준이다.
2. `docs/02-architecture.md`, `docs/03-erd.md` — 공통 아키텍처·ERD
3. `docs/04` ~ `13` — 공통 기능 상세
4. `docs/20` ~ `29`(강성찬), `30` ~ `39`(김민서), `40` ~ `49`(나민서) — 담당자별 상세. 각 문서 끝의 **"ERD 변경 제안", "결정 기록 추가분", "다른 담당자와 맞출 것"** 절을 반드시 읽는다.
5. `scripts/README.md` — 이미 자동으로 검증되는 것 (같은 것을 다시 손으로 확인할 필요는 없다)

## 하지 말 것

- **`docs/`, `scripts/`를 고치지 않는다.** 쓰는 파일은 자기 보고서 하나뿐이다.
- **결정 기록에 이유가 적힌 결정을 "다르게 하자"고 지적하지 않는다.** 예: "로그인 수단이 다르면 별도 계정"은 팀이 이유를 갖고 정한 것이다. 찾는 것은 **문서끼리의 모순, 빠진 것, 동작하지 않는 규칙**이다.
  - 단, 결정이 다른 결정이나 법·보안 요구와 **충돌**하면 보고한다 (그건 모순이다).
- 추측으로 보고하지 않는다. 근거가 되는 파일과 줄을 반드시 적는다. 확인하지 못했으면 "확인 못 함"이라고 적는다.
- 미결로 표시된 것(`미결`, `후속 제안`, `[질문]`)은 결함이 아니다. 4번(완결성) 팀원만 목록으로 모은다.

## 보고서 형식

`verification/reports/{YYYY-MM-DD}/{내 번호}-{역할}.md` 에 쓴다.

```markdown
# {역할} 검증 보고서
기준 커밋: {git rev-parse --short HEAD} · 모델: {모델 이름} · 검증한 문서: {범위}

## 요약
- 높음 N건 / 중간 N건 / 낮음 N건
- 한 줄 총평

## 발견 사항
### [높음] {한 줄 제목}
- **위치:** docs/xx-….md:줄, docs/yy-….md:줄
- **문제:** 무엇이 어긋나는가 (양쪽 원문을 짧게 인용)
- **영향:** 이대로 구현하면 무엇이 잘못되는가
- **제안:** 고칠 방법 (선택지가 여럿이면 나열)
- **담당:** 고칠 사람 (문서 번호대로: 01~13 공통 / 20~ 강성찬 / 30~ 김민서 / 40~ 나민서)
- **확신:** 확실 / 가능성 있음

## 확인했지만 문제 없던 것
- 확인한 항목을 짧게 (총괄이 중복 확인하지 않도록)
```

## 심각도

| 심각도 | 기준 |
|---|---|
| **높음** | 이대로 구현하면 기능이 동작하지 않거나, 보안·개인정보 문제가 생기거나, 두 문서가 정면으로 모순되어 구현자가 어느 쪽을 따를지 알 수 없다 |
| **중간** | 구현은 되지만 일부 상황에서 잘못 동작하거나, 담당자 사이에 다시 협의해야 한다 |
| **낮음** | 용어·숫자·링크 불일치, 설명 부족 등 구현 전에 정리하면 좋은 것 |

## 팀이 특히 알고 싶은 것 (2026-10-06 추가)

이번 검증에서 팀이 꼭 답을 받고 싶은 다섯 가지다. 자기 관점에 해당하는 것은 반드시 다룬다.

1. **확장성** — 사용자·글이 늘거나 서버를 늘릴 때, 또 개인 확장 기능을 붙일 때 공통 설계가 버티는가
2. **기능 사이의 충돌** — 서로 다른 담당자가 정한 규칙이 부딪히는 곳
3. **배포할 때 문제될 것** — 운영 환경(서버 2대, Redis, 파일 저장소, Ollama, 메일)에서 지금 설계대로 안 되는 것
4. **인증·인가** — 로그인, 권한 판정, 관리자, 탈퇴·정지 계정 처리에서 빠진 것
5. **우리가 고려하지 못한 것** — 문서 어디에도 없지만 블로그 서비스에 필요한 것

## 보고서에 반드시 넣을 절: "문서 어디에도 없는 것"

발견 사항과 별도로, 자기 관점에서 **어떤 문서도 다루지 않는 주제**를 모은다. 형식:

```markdown
## 문서 어디에도 없는 것 (우리가 고려하지 못한 것)
| # | 주제 | 왜 필요한가 (없으면 생기는 일) | 제안 (어느 문서에 무엇을 추가) | 심각도 |
```

"있어야 할 것 같다"가 아니라 **없으면 구체적으로 무엇이 잘못되는지**를 적을 수 있는 것만 넣는다.
