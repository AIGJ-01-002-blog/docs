# 총괄 (권장 모델: Fable)

먼저 `verification/prompts/common.md`를 읽는다. 검증 팀원 1~5의 보고서가 모두 끝난 뒤 시작한다.
보고서: `verification/reports/{날짜}/summary.md`

## 임무

다섯 보고서와 스크립트 결과를 하나의 **팀 회의용 최종 보고서**로 만든다. 문서는 고치지 않는다.

## 방법

1. `verification/reports/{날짜}/`의 `00-scripts.txt`, `01` ~ `05` 보고서를 모두 읽는다.
2. **중복 합치기:** 같은 문제를 여러 팀원이 다른 말로 보고한 것을 하나로 합치고, 보고한 팀원을 모두 적는다.
3. **재확인:** "확신: 가능성 있음"이거나 근거 인용이 부족한 지적은 **원문을 직접 다시 읽고** 판정한다.
   - 맞음 → 유지
   - 틀림(문서에 이미 답이 있음, 결정 기록에 이유가 있음) → "기각"으로 옮기고 이유를 적는다
   - 판단 불가 → "사람이 판단" 으로 표시
4. **심각도 재조정:** 팀원마다 기준이 다를 수 있으니 common.md 기준으로 다시 맞춘다.
5. **스크립트 실패**가 있으면 가장 위에 올린다.

## 최종 보고서 형식

```markdown
# 통합 설계 검증 결과
기준 커밋: … · 날짜: … · 총괄 모델: … · 팀원 모델: …

## 한눈에
- 스크립트: PASS/FAIL 요약
- 높음 N / 중간 N / 낮음 N / 기각 N / 사람이 판단 N

## 회의에서 결정할 것 (높음 → 중간 순)
| # | 심각도 | 제목 | 위치 | 선택지 | 담당 | 보고한 팀원 |
|---|---|---|---|---|---|---|

## 담당자별 할 일
### 공통(01~13) / 강성찬 / 김민서 / 나민서
- [ ] …

## 낮음 (한꺼번에 정리)
## 미결 사항 목록 (4번 팀원 목록을 정리)
## 다음 단계(#5 API 명세) 초안 표 위치 (5번 팀원 부록 링크)
## 기각한 지적과 이유
```

각 항목은 **회의에서 30초 안에 결정할 수 있도록** 선택지를 구체적으로 적는다. 예: "숨김 컬럼을 `post.hidden_at`으로 통일(A) / 나민서 안 `post.status = 'HIDDEN'`(B)".

## 최종 보고서에 추가할 절 (2026-10-06)

팀이 특히 알고 싶어 한 다섯 주제(common.md)로 **발견 사항을 다시 묶은 요약**을 "회의에서 결정할 것" 앞에 둔다:

```markdown
## 다섯 가지 질문에 대한 답
### 1. 확장성 — 버티는 곳 / 못 버티는 곳
### 2. 기능 사이의 충돌 — 건수와 가장 큰 것 3개
### 3. 배포할 때 문제될 것
### 4. 인증·인가에서 빠진 것
### 5. 우리가 고려하지 못한 것 (다섯 팀원의 목록을 합쳐 중복 제거)
```

**개선안:** 심각도 "높음"인 항목마다 **바로 적용할 수 있는 수정안**을 적는다 — 어느 문서의 어느 절에, 어떤 문장을 어떻게 바꾸거나 추가할지. 선택지가 여럿이면 각 선택지의 수정안을 모두 적는다. 문서는 고치지 않는다(사람이 결정한 뒤 적용).
